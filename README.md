# Grounded Islamic Reflection Assistant

An evidence-grounded RAG system that maps a user's expressed emotional state
to verified Qur'anic verses, authentic hadith, and du'a, with source-level
citations -- instead of asking an LLM to recall scripture from memory.

> **Status: MVP / v0.** The retrieval and generation pipeline works end to
> end, but the corpus is a small, hand-picked seed set. See
> [Corpus verification status](#corpus-verification-status) before treating
> any output as authoritative.

## Why RAG, not just an LLM

An LLM asked to "give me a dua for anxiety" will happily invent plausible
Arabic, mistranslate a verse, or attach the wrong citation -- and most
readers can't tell. This project is designed so the model is never the
source of religious truth:

```text
User: "I feel anxious about whether I'll succeed."
        |
        v
LLM call #1: classify the feeling
        -> {emotion: "anxiety", intent: "comfort", themes: ["uncertainty", "trust in allah"]}
        |
        v
Vector retrieval over a curated, metadata-tagged corpus
        -> top matching Qur'an / hadith / du'a entries, each pre-verified with a citation
        |
        v
LLM call #2: write ONLY an empathetic wrapper + short "why this helps" note
        -> the Arabic / transliteration / translation / citation are rendered
           straight from the corpus JSON, never re-generated by the model
        |
        v
Result card, or an honest "no verified reminder found" message if nothing
matched well enough -- the app never falls back to inventing a source.
```

The one design decision that matters most: **the LLM never outputs sacred
text.** `src/generate.py` only asks the model for a human-sounding opening
line and a short explanation of relevance; every citation, Arabic string,
transliteration, and translation shown in the UI comes directly from
`data/corpus.json`, and any id the model references that isn't in the
retrieved set is silently dropped. If retrieval finds nothing above the
similarity threshold, the LLM generation call is skipped entirely and the app
says so -- zero hallucination surface in that path by construction.

## Architecture

- **`app.py`** -- Streamlit UI: emotion buttons + free-text box, a result
  card per source, and a "give me another reminder" button that re-runs
  retrieval excluding what's already been shown.
- **`src/classify.py`** -- one LLM call that turns free text into a
  structured `{emotion, secondary_emotions, intent, themes}`. Falls back to a
  safe default (no themes, intent "comfort") if the model call or JSON
  parsing fails, so a flaky LLM never crashes the app.
- **`src/retrieval.py`** -- embeds the corpus with
  [fastembed](https://github.com/qdrant/fastembed) (`BAAI/bge-small-en-v1.5`,
  ONNX-based, no torch) and searches a `faiss` `IndexFlatIP` (cosine
  similarity via L2-normalized vectors), with a small score boost for
  theme-tag overlap with the classification step.
- **`src/generate.py`** -- the constrained generation step described above.
- **`src/corpus.py`** -- loads and schema-validates `data/corpus.json`.
- **`data/corpus.json`** -- the curated library itself (see schema below).
- **`scripts/verify_corpus.py`** -- optional helper to cross-check Qur'an
  entries against the public Quran.com API (see
  [Corpus verification status](#corpus-verification-status)).

## Corpus schema

Every entry in `data/corpus.json` carries:

| Field | Meaning |
|---|---|
| `id` | stable unique identifier |
| `source_type` | `"quran"` \| `"hadith"` \| `"dua"` |
| `surah`, `surah_name`, `ayah` | for Qur'an entries |
| `hadith_collection`, `hadith_number`, `narrator` | for hadith entries |
| `authenticity` | e.g. `"Qur'an"`, `"Sahih (Bukhari)"`, `"Sahih (Muslim)"` |
| `arabic`, `transliteration`, `translation` | the text itself |
| `themes` | lowercase keywords used for retrieval boosting (e.g. `"anxiety"`) |
| `intents` | which of `comfort/forgiveness/gratitude/guidance/patience/protection` this serves |
| `notes` | one-line context for why this source is relevant |
| `citation` | human-readable reference shown in the UI |
| `verified_against_source` | see below -- **currently `false` for every entry** |

## Corpus verification status

**Every entry currently has `"verified_against_source": false`.** The
seed corpus was written from well-established, widely-published wording of
very well-known ayat and hadith, but it was assembled without the ability to
cross-check against a live authoritative source: this project was scaffolded
in a sandboxed environment whose network egress is restricted to an
allowlist that does not include `api.quran.com` or `sunnah.com`.

Before relying on this for real users:

1. Run `python scripts/verify_corpus.py` locally (needs normal internet
   access) to diff each Qur'an entry's stored Arabic against
   [Quran.com](https://quran.com)'s API.
2. Manually check every hadith entry's collection + number against
   [Sunnah.com](https://sunnah.com).
3. Ideally, have someone with `ijazah`-level or scholarly familiarity review
   the corpus before it's presented as authoritative to end users.
4. Flip `verified_against_source` to `true` entry-by-entry as you confirm
   each one, and remove the `⚠️` warning users see under unverified
   entries in the UI (`app.py`, `render_source`).

The `2:255` (Ayat al-Kursi) and `1162` (istikharah) entries are especially
worth checking first -- they're abbreviated/paraphrased in the seed corpus
rather than given in full, specifically to avoid guessing at long text from
memory.

## Setup

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # fill in LLM_BASE_URL / LLM_API_KEY / LLM_MODEL
streamlit run app.py
```

The first run downloads a small ONNX embedding model (~100MB) via
`fastembed`; subsequent runs use the local cache.

### LLM provider

The app talks to any OpenAI-compatible chat completions endpoint (see
`src/llm_client.py`), configured entirely through environment variables:

- **Groq's free tier** (recommended to start): create a key at
  [console.groq.com](https://console.groq.com), no credit card required, and
  set `LLM_BASE_URL=https://api.groq.com/openai/v1`.
- **A local OpenAI-compatible server** (vLLM, Ollama, LM Studio): point
  `LLM_BASE_URL` at it instead -- nothing else in the code changes.

## Tests

```bash
pytest
```

`tests/test_corpus.py` validates the corpus schema (fast, no network).
`tests/test_retrieval.py` exercises the embedding + retrieval pipeline and
skips itself if the embedding model can't be downloaded in the current
environment (e.g. restricted CI).

## Roadmap / possible extensions

- Expand the corpus well beyond the ~19 seed entries, ideally with scholarly
  review, and swap the abbreviated entries (Ayat al-Kursi, istikharah) for
  full verified text.
- Replace the theme-overlap boost with metadata filtering (e.g. only
  `intent: "forgiveness"` sources when that's the classified intent).
- An agentic router that branches by intent before retrieving (comfort ->
  Qur'an/dhikr, forgiveness -> tawbah/istighfar sources, decision ->
  istikharah material) instead of one flat retrieval call -- not needed for
  the MVP, but a natural next step once the corpus is large enough that flat
  retrieval starts missing things.
- Retrieval evaluation: a small labeled set of (feeling -> expected
  theme/source) pairs to measure retrieval quality as the corpus grows.
